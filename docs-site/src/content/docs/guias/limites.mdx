---
title: Límites de peticiones
description: Cuántas peticiones admite cada clave, los encabezados RateLimit y cómo reintentar tras un 429.
---

| Qué                                   | Límite                          |
| ------------------------------------- | ------------------------------- |
| Cada clave de API                     | 120 peticiones por minuto       |
| Cada sesión del panel                 | 600 peticiones por minuto       |
| Intentos con claves inválidas, por IP | 30 por minuto                   |
| Rutas de sesión (`/api/auth/*`)       | Límite por IP                   |
| Registros con un mismo correo         | 5 por hora (con confirmación)   |
| Reenvíos del enlace de confirmación   | 3 por correo y hora; luego `429 demasiados_reenvios` |
| Enlaces de confirmación al entrar sin confirmar | 6 por correo y hora (contando los del registro) |
| Enlaces para recuperar la contraseña  | 3 por correo y hora; luego no se envían más (la respuesta no cambia) |
| Intentos con contraseña al confirmar el correo | 5 por cuenta y hora; 10 cada 5 minutos por IP |
| Organizaciones propias por persona    | 10                              |
| `POST /dte/consultar-mh`, por clave   | 20 por minuto                   |
| `POST /dte/consultar-mh`, por organización | 1000 por día               |
| Tamaño del cuerpo                     | 512 KB                          |

En una instalación propia, el límite por clave se cambia con la variable `LIMITE_CLAVE_POR_MINUTO`; los de `consultar-mh`, con `CONSULTA_TERCERO_POR_MINUTO` y
`CONSULTA_TERCERO_POR_DIA`.

Los topes por correo sólo existen si la instalación envía correos de cuenta. Los de `/api/auth/*`
responden con el formato de Better Auth (`{ "code", "message" }`).

## Encabezados

Toda respuesta autenticada con clave de API trae:

```http
RateLimit-Limit: 120
RateLimit-Remaining: 117
RateLimit-Reset: 42
```

`RateLimit-Reset` son los segundos que faltan para reiniciar la ventana.

## Al exceder el límite

`429 limite_excedido` con el encabezado `Retry-After` (segundos) y `details.reintentarEn`:

```json
{ "error": { "code": "limite_excedido", "message": "…", "details": { "reintentarEn": 18 } } }
```

Espera `Retry-After` segundos y reintenta. Si era una emisión, usa la **misma**
[`Idempotency-Key`](/guias/idempotencia/). La CLI termina con código de salida `4` y muestra el
`Retry-After`.

Un cuerpo de más de 512 KB recibe `413` con el código `datos_invalidos`.
